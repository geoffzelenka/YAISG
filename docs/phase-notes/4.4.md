# Phase 4.4 — Estate, realm, map, relocation, and caps client

Implemented the Phase 4 client surface described by design v0.5 §9 and added the
non-mutating relocation preview endpoint.

## Built

- Activated Estate, Realm, and Map routes in the authenticated sidebar.
- Added an estate view with form identity and specialty tags, active/inert/empty
  upgrade slots, content-driven upgrade costs and affordability, purchase cache
  invalidation, and confirmed content-driven transformations with slot/cap impact.
- Added profile and realm development-node identity, tags, active modifiers,
  projects, clamped contribution controls, outgoing-edge progress, and prominent
  pending-transition countdowns.
- Reused the existing 4 Hz action clock for realm and relocation countdowns. Due
  transitions invalidate realm and available-action queries; due relocation
  invalidates profile, estate, and available-action queries so lazy server
  finalization is observed.
- Added a simple SVG realm graph with current-realm highlighting, labeled nodes,
  edge-cost tooltips, and destination selection.
- Added `GET /characters/me/relocate/preview?realm_id=` as a thin, non-mutating
  wrapper around the same path/form cost calculation used by relocation. The
  relocation confirmation surfaces final action rewards and the stopped-action
  notice in the global reward feed.
- Updated `useContent()` to type, fetch, and version-cache `map`, `estate_forms`,
  `development`, and `projects`; stale version keys remain pruned safely.
- Changed inventory capacity display to use `caps.inventory_slots.effective` from
  the profile rather than the content base cap.

## Tests

- Added Vitest/Testing Library coverage for slot states and inert tooltips,
  affordability gating, shared-clock transition expiry/refetch, contribution
  clamping, relocation preview/confirm, and effective-cap display.
- Added API integration coverage proving relocation preview returns the expected
  terms without charging or moving the estate.

## Deviations and non-goals

- The placeholder content has only an estate-upgrade-slot form cap, so the
  transformation dialog reports that concrete delta and states that the full form
  cap/modifier source changes on confirmation.
- No upkeep, decay, solvency, production, regression traversal, transfer/escheat,
  or inter-realm balancing behavior was added. Dormant content fields remain
  display/validation data only.

## Review corrections

- Expired countdowns retry invalidation once per second while their server state
  remains pending and re-arm when a new completion deadline is rendered. This
  prevents clock skew or chained transitions from stranding a `0:00` banner.
- Map nodes without presentation coordinates, and edges touching them, are skipped
  safely. Zero-valued project/development targets render as complete rather than
  producing an invalid percentage.
- Relocation preview now lazily finalizes a due prior arrival before calculating
  the next route, matching estate/profile read behavior.
- Contribution mutations now carry their response type, and relocation errors show
  stable API error codes consistently with estate errors.
