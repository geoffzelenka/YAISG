# Prompt 4.1 — v0.5 structural realm and estate model

Implemented the four validated content packs (`map`, `estate_forms`,
`development`, and `projects`) and reshaped realms to reference starting
development nodes. The loader enforces cross-pack realm, form, item, node,
edge, project, relocation-class, graph, and award integrity. All nine public
packs use the existing canonical hashing, manifest, ETag, and cache behavior.

The Phase 3 realm-tier content model was removed. Pure engine state now selects
modifier, availability, and cap sources by development node and estate form,
then includes installed upgrades only when their realm tags are active. Added
cheapest-path cost resolution (ordered by gold, then time) and relocation-class
scaling with integer truncation. No transition, regression, relocation,
upkeep, production, treasury, or project-award mechanics were implemented.

Alembic revision `0006` renames and expands estates, adds residence and
ownership history, and creates the graph/project state tables. Existing estates
backfill to `form.homestead`; new characters atomically receive a `form.camp`
estate, history row, home-estate link, and realm state. The checked-in Phase 3
head did not contain the old `realm_state` or `realm_contributions` tables
described by the prompt, so their final v0.5 shapes are created directly rather
than transformed. Existing Phase 3 estates also have no creation timestamp, so
their history uses the owning character's creation timestamp as the closest
available original timestamp.

Design-document amendments needing ratification:

- §5.1's five-pack served list is superseded by the nine-pack list.
- `estates.relocating_to_realm_id` and `relocation_completes_at` extend §6.2,
  mirroring realm transition state for Prompt 4.3.

No new dependency was added. Existing engine tests that constructed the removed
realm/tier state were updated to construct development-node/form state instead.

Review follow-up added dialect-independent reflection of the legacy estate
unique constraint, automated populated-Phase-3 migration/backfill/downgrade
coverage, four-node path and tie-break coverage, upgrade-derived API cap
coverage, and the missing unknown-map-realm fixture. Realm state is pre-seeded
by migration, while character creation also uses an isolated savepoint so a
concurrent initializer cannot be reported as a name collision. PostgreSQL 16
upgrade and downgrade were exercised directly after these changes.
