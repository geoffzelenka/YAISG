# Prompt 2.2 — Character creation and profile

Implemented the first persistent character aggregate and the post-login profile flow.

## Server

- Added Alembic tables for characters, per-skill progression, currency, estates,
  installed estate upgrades, and inventory stacks. Estates use their own UUID and
  store `upgrade_slots` as required.
- Added atomic `POST /characters`, including all requested stable error codes,
  case-insensitive global names, and database-backed one-character enforcement.
- Character creation initializes every placeholder content skill at 0 XP, starting
  gold (the `STARTING_GOLD` config constant, default 100), an unused zero premium
  balance, and a level-one estate using the content cap for its slots.
- Added profile and inventory endpoints. Profiles return realm content modifiers,
  estate state, and server-derived skill level/progress values.
- Profile reads lazily seed skill rows introduced by newer content packs and repair
  stale cached levels from the canonical XP curve, logging the repair.
- Added the pure `level_for_xp` engine function and boundary/monotonicity tests.

## Client

- Authenticated users without a character are routed to a creation form populated
  from the cached placeholder realm content, including tags and modifiers.
- Users with a character see the live Profile panel with realm, gold, skills, and
  XP progress bars. Sidebar grouping follows §9.1; unfinished sections remain
  visibly marked coming soon and Exploration is disabled.

## Deviations and scope

- A normalized name column enforces case-insensitive uniqueness consistently on
  SQLite and PostgreSQL rather than relying on database-specific collations. Names
  are trimmed before validation and must contain 3–20 ASCII letters, numbers, or
  internal spaces; the display-name column does not carry a redundant constraint.
- The v1 one-character rule is also a unique database constraint on `player_id` to
  make concurrent double-submit safe. A future multiple-character feature will
  need to remove that constraint in its migration.
- Inventory display polish, premium mechanics, Exploration, and all other §10
  non-goals were intentionally excluded.
- The character integration suite uses `httpx.AsyncClient` with `ASGITransport` so
  its concurrent SQLite double-submit test exercises the application without the
  synchronous TestClient hang seen in the shared development environment.
