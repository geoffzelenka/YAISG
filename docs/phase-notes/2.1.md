# Prompt 2.1 — Content pipeline and placeholder pack

## Built

- Added strict, frozen Pydantic schemas for skills/actions, items, realms,
  projects, estate upgrades, modifiers, caps, and the level 1–99 XP curve.
- Added a startup loader that validates all required packs, rejects unknown
  packs, cross-checks item, skill, and realm-tag references, rejects duplicate
  IDs, and produces an immutable typed lookup index.
- Added canonical SHA-256 hashing. The overall version includes the engine-only
  XP curve; public pack hashes cover `skills`, `items`, `realms`, `upgrades`,
  and `caps` and are used as strong ETags.
- Added public content manifest/pack endpoints with `If-None-Match`/304 support.
- Added an obviously synthetic placeholder dependency chain: three gathering,
  two refining, and two crafting actions; an empty combat-monsters skill shape;
  ten fake items; two realms/projects; and two estate upgrades.
- Added a deterministic checked-in XP generator. Level 1 starts at zero and
  each following level adds `floor(100 * 1.12 ** (level - 2))` cumulative XP.
- Added an app-load client provider and typed `useContent()` hook. It checks the
  manifest on load, fetches changed packs, and stores packs in localStorage keys
  namespaced by content version.

## Decisions and deviations

- XP affects the overall server content version but is not exposed as a client
  pack because Prompt 2.1 explicitly limits pack endpoints to five named packs.
- Content endpoints are unauthenticated so the app can populate its cache before
  login. Gameplay remains server-authoritative; cached content is display data.
- `*` is accepted as the cross-realm availability wildcard described by the
  design example. Other action and upgrade realm tags must exist on a realm.
- Combat contains only its requested content container; no combat mechanics or
  invented encounters were added. Exploration and all other §10 non-goals were
  left untouched.

## Verification

- Game service: Ruff and mypy clean; 22 tests pass under the target Python 3.12
  container.
- Auth service: Ruff and mypy clean; 15 tests pass.
- Client: ESLint, Prettier, TypeScript, four Vitest tests, and production build
  pass.
- `docker-compose up -d --build` starts all three services. Health, manifest,
  client HTML, strong ETag, and live 304 responses were exercised successfully.

## Review follow-up

- Fixed XP monotonicity validation to include the level 1 to level 2 boundary.
- Made browser cache writes and cleanup best-effort, and prune content keys from
  stale versions after successful loads without affecting unrelated storage.
- Restricted the authentication bypass to the manifest and five known public
  pack paths rather than the entire `/content/` prefix.
- Added comma-list and wildcard `If-None-Match` support plus `public, no-cache`
  response policy so unversioned pack URLs are always revalidated.
- Removed runtime type-narrowing assertions and the redundant client memo.
- Added regression coverage for the first XP transition, public pack hash
  changes, conditional-request variants, storage quota failures, and stale-key
  pruning.
