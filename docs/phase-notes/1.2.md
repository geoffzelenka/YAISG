# Prompt 1.2 — Game API auth and client auth flow

Implemented end-to-end Phase 1 authentication:

- The game API verifies RS256 bearer tokens against a TTL-cached auth-service JWKS, validates issuer/expiry/signature, refetches for unknown key IDs, and returns uniform error envelopes.
- Added the `players` migration, model, idempotent first-request provisioning, and temporary `GET /players/me` endpoint.
- Enabled credentialed client-origin CORS on both APIs and configured Compose with the internal JWKS URL and automatic game migrations.
- Added in-memory client access tokens, credentialed login/register/refresh/logout, one-refresh 401 retry behavior, silent startup refresh, protected React Router routes, and TanStack Query player loading.
- Added the Phase 1 placeholder shell with the static §9.1 labels. Exploration and every panel remain explicitly “coming soon.”

Tests cover valid, expired, wrong-issuer, and bad-signature tokens; player provisioning idempotency; and the client 401 refresh/retry path.

Review follow-up hardened unknown-key JWKS refreshes with a global retry floor and bounded negative cache, made CORS wrap authentication failures, handled a second 401 after refresh, and added direct JWKS cache/CORS coverage.

Deviations: none. No gameplay, real content, or §10 non-goals were added. Sync SQLAlchemy sessions, per-section placeholder routes, and a non-root production container remain planned later-phase work.
