# Phase 4.3 — Realm endpoints and relocation

Implemented the realm development gameplay and relocation API described by design
v0.5 §§5.6, 7.2, and 7.4.

## Built

- Added the internal `award_edge_progress` interface. It serializes on realm state,
  rejects regression/non-outgoing edges, and opens the content-defined transition
  window when the target is reached.
- Added concurrency-safe lazy realm finalization. Arrival changes the node, clears
  transition state, resets every outgoing gauge from the departed node, and closes
  projects not offered by the destination node.
- Added `GET /realms`, `GET /realms/{id}`, and the pure-content `GET /map` response.
  `/map` is deliberately unauthenticated, matching the existing public-content
  rationale in design log #8. Treasury remains private.
- Added clamped project contributions with inventory consumption and audit rows.
  Project completion and all edge awards occur in the contribution transaction;
  locking makes completion single-effect under racing final contributions.
- Added relocation with cheapest-path cost, estate-form multipliers, up-front gold
  and item charging, instant and delayed arrival, residence-cache synchronization,
  and final active-action rewards in the response.
- Wired realm-transition and relocation finalization into character resolution, so
  normal action polls observe due state changes. Estate reads also finalize moves.
- Added content-index lookups for development edges and projects and focused service
  tests for award validation, transition reset/closure, idempotence, and relocation.

## Rules recorded for ratification

- Once a realm transition is pending, awards to every edge of the departing node are
  rejected as `INVALID_EDGE_AWARD` internally. Progress would be discarded at arrival,
  so accepting it would be misleading.
- During delayed relocation, the estate and character retain the origin realm identity
  until arrival. Ordinary actions may still start under origin rules, but a second
  relocation is rejected with `ESTATE_BUSY`.
- Contributions are intentionally not restricted by residence. The prompt's validation
  contract names project/node and inventory checks but no local-residence rule or error.
  Cross-realm requests therefore lock every involved realm in sorted ID order after the
  character lock, preventing opposite-direction PostgreSQL deadlocks.
- Relocation resolves and then clears an active action. Completed-cycle rewards are
  returned in `final_rewards`; incomplete work is abandoned.

## Deviations and non-goals

- Upgrade applicability is not stored in this codebase; it is derived from the current
  realm node on every estate/profile resolution. Consequently arrival re-evaluates
  inert upgrades without a persistence write beyond the realm move itself.
- No treasury writes, regression traversal/filling, transition cancellation, upkeep,
  decay, solvency, production, transfer/escheat, or inter-realm balancing mechanics
  were added.

## Review corrections

- Contributions now return `REALM_TRANSITIONING` before consuming goods when a node is
  already leaving, rather than allowing an internal award error to escape as HTTP 500.
- Multi-award projects process awards in content order. If an award fills its edge and
  starts departure, remaining awards are skipped because the realm is then subject to
  the no-further-awards-during-transition rule.
- Realm-list SQLite write intent is acquired once, so the list finalizes in one
  transaction. Concurrent first-touch realm creation uses a savepoint and re-fetch.
- Relocation reuses checked inventory rows for charging and returns the shared typed
  reward response model.
- API coverage now exercises public map access, contribution clamping/conservation and
  completion awards, transition rejection, delayed/instant relocation, lazy arrival,
  and unreachable-route rollback.
