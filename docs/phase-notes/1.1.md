# Phase 1.1 — Auth service

Implemented the auth-owned UUID schema through Alembic, Argon2 password storage,
RS256 access tokens, persistent first-boot key generation, JWKS publication, and
the register/login/refresh/logout lifecycle. Register and login have a rolling
in-process per-IP limit of five requests per minute. API failures use stable
`{error: {code, message}}` envelopes.

Refresh credentials are random opaque values stored only as SHA-256 hashes. Every
successful refresh revokes its old row and creates a replacement. Because the
required schema has no explicit family identifier, the token family is interpreted
as all refresh tokens for the user; reuse therefore revokes every active refresh
token belonging to that user.

Compose now runs the auth migration before serving and persists keys in
`/data/auth-keys`. Production deployments must set `AUTH_COOKIE_SECURE=true`; it
defaults to false for the localhost HTTP development stack.

Tests cover the complete lifecycle, duplicate email, weak and incorrect passwords,
rotation, family revocation after reuse, expiry rejection, and verification through
the published JWKS. No game-service code or out-of-scope account features changed.

Review hardening added credentialed browser CORS, uniform login failures with a
dummy Argon2 verification, a 1024-character password ceiling, atomic refresh
rotation, safe expired-token retries, constant-time refresh hash comparison, and
bounded rate-limit state with an explicit trusted-proxy allowlist. Signing keys are
now initialized lazily and injected into tests from temporary directories.
